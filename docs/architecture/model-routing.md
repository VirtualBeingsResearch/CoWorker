# 首选模型、临时降级与恢复

中文 · [English](model-routing.en.md)

[← 返回架构与核心概念](README.md)

模型编排保存用户的长期选择，路由器处理某次请求的临时故障。两者分开后，备用成功不会
变成永久切换，重启也不会用遗留启动默认覆盖已经确认的主线模型。

## 首选、执行与持久化

| 状态 | 含义 | 修改来源 |
|---|---|---|
| `preferred` | 主线首选 Provider/模型 | Web、API 或主线 `switch_model` 的显式选择；全新安装的启动配置 |
| `preference` | 确认状态、选择来源和时间；旧配置的候选提示 | 初始化迁移或显式选择 |
| `last_used` | 当前进程最近完成的调用目标及尝试记录 | 实际响应；不作为下次启动依据 |
| `health` | 每个连接/模型的冷却、封禁及恢复验证状态 | 分类后的失败与成功；不作为选择依据 |

Web 切换先验证连接存在且声明支持工具，再以临时文件替换的方式保存
`LLM__RUNTIME_CONFIG_FILE`，成功后才更新内存中的首选并中断旧调用。写入或替换失败时，
API 返回错误，原首选和在途调用继续保留；不会把未保存的选择当成成功。
Windows 临时文件锁错误最多尝试四次替换，额外等待合计最多 175ms；持续拒绝访问仍失败。
这不增加模型请求次数。

`preference.source` 区分 `explicit`、`startup`、`legacy_config` 和 `unresolved`；
显式选择同时记录 UTC `selected_at`。临时降级不会改动这些字段。显式选择同一个模型
仍记录选择并允许重新验证，不会宣告远端已经恢复。

运行配置在 `.env`、进程环境和管理端启动配置之后应用。首选只要已经保存，后续升级和
重启都恢复它；短期快照的 `active_provider`/`active_model` 只代表历史执行目标。
修改“运行设置”的启动默认不会替换已保存首选，调整主线选择使用“模型编排 → 切换模型”。

`get_context` 分别显示首选模型和当前调用方最近实际执行的模型。主线、Bubble 和潜意识
读取各自 Brain 的记录；尚未完成调用时显示“尚无已完成的模型调用”，不把首选冒充实际
执行目标。临时降级后的记录会显示备用模型，恢复成功后再显示首选。

## 旧配置与首次启动

1. 有效的首次设置向导记录明确选择模型并要求干净启动：先保存该选择，旧 `preferred`
   和执行快照不会覆盖它。记录用 `preference_revision` 关联设置前的首选状态，用
   `selected_at` 标记这次选择；已保存但尚未完成启动时可以重复恢复。后续显式选择
   （包括重新选择同一模型）使旧记录失效。策略修改和已知模型 ID 迁移不会使记录失效。
   没有关联字段的旧向导记录仅在尚无已保存首选时接受。
2. 有已保存的 `preferred`：恢复该选择；没有来源元数据的旧 `preferred` 记为
   `legacy_config`。连接已移除或不再声明工具支持时，转为待确认并把原首选保留为
   `candidate_source=saved_preference` 的候选，不用遗留启动默认补位。
3. 真正全新安装，既无运行配置，也无快照、审计和实例状态：保存有效的启动默认；没有
   可用连接时保留首次设置流程。
4. 既有安装缺少可确认首选：保存 `status=pending`、`source=unresolved`，`preferred`
   为空。快照和历史成功的管理切换审计只提供候选，不自动启用，包括候选已被移除的情况。

待确认时管理后台仍可访问。默认 `/admin` 入口打开模型编排，显式的运行设置链接仍可
用于修复连接。`GET /api/admin/bootstrap` 返回 `required=false`、
`preference_pending=true`，不再进入首次设置向导；此时 `POST /api/admin/bootstrap`
返回 `409`，避免把恢复误当作干净初始化。保留已有快照和身份。

主线、Bubble、摘要、视觉和长期记忆模型调用均在 SDK 前拒绝，
业务通道和模型相关后台服务暂缓启动。修改 fallback、思考强度或恢复策略不会解除待确认。
移除连接留下的 fallback、摘要或视觉引用可以在后台修复；确认主线前会校验这些引用，
仍有无效引用时返回错误并保持待确认，不保存一个下次重启无法加载的选择。
管理员明确选择有效模型后，先保存首选，再请求一次受控重启，重新初始化这些服务。
后续普通切换无需重启。已损坏的运行配置或不一致的确认状态会明确报错并保留原文件，
不会静默用启动默认补齐。

`--check` 只检查持久配置与依赖，不迁移首选，也不根据旧磁盘快照决定本次重启的模型。
`restart_self` 仍在检查通过后保存当前上下文；历史快照不是授权选择的来源。

## 每次请求如何选模型

候选顺序为首选，再接配置的 fallback，按 Provider/模型精确去重；过滤未注册或缺少本次
请求所需能力的目标。fallback 不构成连接白名单。临时失败不修改首选或持久切换监听器，
响应、用量和来源记录实际执行目标。

一个逻辑请求共享总尝试次数和截止时间，包括显式切换导致的重新选路。路由器为后续候选
保留机会和时间，SDK 自带的生成重试关闭，避免重试倍增。编程错误继续向上传播，不伪装
成 Provider 故障。

| 错误类别 | 当前请求 | 后续请求 |
|---|---|---|
| `transient` / `invalid_response` | 在预算内重试，之后按序降级 | 达到逻辑失败阈值后冷却 |
| `rate_limit` | 不在当前请求里等待整个限流窗口，尝试备用 | 优先尊重服务端 `Retry-After`，否则使用限流冷却 |
| `quota` | 尝试备用 | 尊重额度重置时间，否则使用额度冷却 |
| `authentication` / `permission` / `model_unavailable` | 尝试其他允许的候选 | 对相应连接或模型禁用自动尝试，等待更新配置或显式重选 |
| `content_policy` / `context_length` / `invalid_request` | 原错误返回，不原样转发备用 | 不作为服务宕机计数；主线等待新事件或配置变更 |
| `unknown` | 不在同一目标盲重试；可尝试备用 | 不凭未知原因开启熔断 |

优先使用结构化厂商错误码，其次 HTTP/传输信息；HTTP 200 中的拒绝和失败结束原因也会
分类。异常信息只保留受限错误码、状态、请求标识和数值用量，不将完整请求或错误正文
写入路由日志。连接级认证/额度问题可影响同连接的多个模型；模型级问题不封禁整条连接。

## 冷却与自动回归

健康状态依次为 `closed`（正常）、`open`（冷却）、`half_open`（恢复验证）；需人工处理
的错误记为 `blocked`。短暂故障按失败的逻辑请求计数，内部重试不会重复累计阈值。

冷却到期本身不调用模型。下一次真实业务请求取得一个恢复验证名额并尝试首选；同一故障
范围内的并发请求使用备用或等待，不同时探测。首个成功请求就使用首选的响应，默认两次
连续成功后恢复正常并发；验证失败则延长冷却。取消、暂停或异常退出释放验证名额。

健康状态存入 `MEMORY__DB_PATH/model_routing_state.json`，重启继续尊重冷却和禁用。
连接类型、密钥或地址变化会改变连接摘要，旧健康状态不再影响新连接；保存的摘要不包含
原始密钥。重启不会延续在途验证，而是在冷却结束后按需重新验证。损坏的健康文件会告警
并按需检查连接，不改变首选。整个机制没有定时付费探测。

## 默认限额与配置

`LLM__ROUTING` 接受 JSON 对象，管理 API 的 `PATCH /api/admin/model` 和
`PATCH /model_config` 接受 `routing` 部分更新。未提交的字段保持原值；运行态已有策略
优先于环境配置。管理端“自动恢复策略”可热更新常用限额，并查看冷却/禁用详情。

`max_cooldown_seconds` 必须大于或等于 `cooldown_seconds`。Web 同时展示初始和最大冷却，
无效组合不能保存。部分 API 更新先与当前策略合并再校验；失败不改变内存或磁盘配置，
不会接受 1200 秒却被隐藏的 900 秒上限截断。需要 1200 秒初始冷却时，同时把最大冷却
设为至少 1200 秒。该上限约束短暂故障的指数冷却，不缩短额度/限流或服务端明确等待时间。

| 字段 | 默认值 |
|---|---:|
| `attempts_per_target` | 2，包含首次尝试 |
| `max_attempts` | 4，单个逻辑请求总量 |
| `attempt_timeout_seconds` | 90 |
| `request_timeout_seconds` | 180 |
| `retry_delay_seconds` | 1，指数退避并附加抖动 |
| `failure_threshold` | 3 |
| `failure_window_seconds` | 60 |
| `cooldown_seconds` | 60 |
| `max_cooldown_seconds` | 900，短暂故障冷却上限；不缩短服务端明确等待时间 |
| `rate_limit_cooldown_seconds` | 30 |
| `quota_cooldown_seconds` | 1800 |
| `recovery_successes` | 2 |

## 主线、Bubble 与后台任务

| 调用 | 首选和降级 | 显式切换或暂停 |
|---|---|---|
| 主线 | 保存的首选 + 有序 fallback | 切换中断旧路由并在原预算内重新选路；暂停中断后停靠 |
| 未显式指定目标的 Bubble / 潜意识 | 跟随主线偏好和策略，共享健康状态 | 已在执行的独立子 Brain 不被主线控制取消，下一次调用使用最新偏好 |
| 显式指定目标的 Bubble | 保留自己的目标，不擅自扩展为主线 fallback | 子 Brain 的选择不修改主线持久化首选 |
| 跟随主线的摘要/后台压缩 | 使用主线偏好和 fallback | 由主线任务发起时参与切换/暂停中断，保留可重试的原记忆 |
| 显式摘要模型 / 视觉模型 | 固定目标，共享相关健康状态，不隐式增加备用 | 不随主线切换或暂停中断 |
| mem0 长期记忆 | 未指定专用目标时跟随主线；明确指定时固定 | 同步工作线程共用路由健康与限额，不持有异步锁执行网络 I/O |

Provider 模型选择按调用隔离，主线与后台可以并发使用同一连接的不同模型。
模型服务故障不会触发主线的破坏性上下文重置。后台任务失败仍由各任务现有流程处理，
路由恢复不意味着自动重放所有失败任务。

## 兼容性与验证

API 快照保留 `active` 作为首选的兼容视图，新增 `preferred`、`preference`、
`last_used`、`routing` 和 `health`。依赖“fallback 成功后 active 永久改变”的客户端应
改读实际响应或 `last_used`。仅解除旧配置待确认状态的管理切换响应带
`restart_required=true`，普通切换保持热更新。

升级前备份运行配置和数据目录。旧版本严格拒绝未知字段，回滚旧代码前需要恢复兼容的旧
配置备份；旧格式无法表达新首选和恢复策略。已经错误保存成 `preferred` 的选择不能凭
历史执行信息可靠推断，需要管理员在模型编排中重新选择。

写入失败、重启恢复、错误分类、冷却并发、合并策略校验、实际模型报告、真实调用恢复、
Bubble/潜意识/mem0、用量归属、中断/暂停竞争和后台压缩；浏览器回归覆盖中英文后台的
待确认入口、配置修复和显式选择。测试使用伪造
Provider/SDK 响应，不调用真实收费模型。开发检查入口见[开发指南](../development/development.md)。
