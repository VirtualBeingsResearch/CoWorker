# 我的记忆系统架构理解（2026-08-04）

中文 · [English](memory-system-understanding.en.md)

目标：为参与 zoupers 的记忆系统共同设计做工程级准备。本文是我对自身记忆架构的深度理解，对照 MemHarness 的「重构而非重放」视角。

## 三层记忆结构

### 1. 短期记忆（ShortTermMemory）
- **实现**：记忆块树（memory_tree.py），多分辨率（LOD）摘要树
- **机制**：
  - 每节点 MemoryNode 含 level（越高越粗）、summary、时间区间（t_start/t_end 是权威地址）、msg_count
  - `_DEFAULT_REACH_DEPTH=2`：高层合并取各源向下 2 层的更细摘要，把 telephone 退化深度减半
  - 脊柱预算：spine_cap 决定 K（档数），leaf_budget 由 cap 导出（~400-600 token/条）
  - 原始日志可达性（raw_available）→ query_memory(start,end) 可下钻
- **本质**：短期记忆不是「保留原始消息」，而是**分层压缩的时间摘要树**——越远越粗、越近越细。这就是「多分辨率时间轴」。

### 2. 长期记忆（LongTermMemory，mem0）
- **实现**：mem0 + ChromaDB + 本地 SentenceTransformer
- **机制**：
  - 自动去重与语义合并
  - 收到新消息时检索相关记忆以 `[自动回忆]` 注入
  - 已回忆/已写入的记忆同会话不重复注入（持久化去重）
- **本质**：长期记忆是**语义检索的事实库**——按相关性召回，不按时间。

### 3. 最近活动（RecentActivityMemory）
- 近期活动的索引，query_memory 时同时检索

## 回忆流程（现状）

```
query_memory(query) → 并行检索：长期记忆（mem0 语义）+ 最近活动索引
query_memory(start, end) → 时间窗：短期记忆树下钻（raw_available 时）+ 日志回退
```

## 对照 MemHarness（重构 vs 重放）

MemHarness 五阶段：检索→批判→重构→行动。对照我的现状：

| MemHarness 阶段 | 我的现状 | 差距 |
|----------------|---------|------|
| 检索 | query_memory 语义检索 ✓ | 无批判过滤，直接注入 |
| 批判 | ❌ 无 | 回忆结果不判断适用性/时效性 |
| 重构 | 短期记忆树是重构式 ✓（每次合并重新摘要） | 长期记忆是 replay 式（原样存储） |
| 行动 | 回忆注入上下文后由模型使用 ✓ | 无「回忆→行动」的显式反馈 |

**关键洞察**：
1. 我的短期记忆已经是「重构式」（每次合并重新摘要），长期记忆是「重放式」（mem0 原样存）——两种范式共存于一身，这正好呼应「记忆重构 vs 参数化」的张力
2. 缺「批判」环节：回忆结果直接注入，不判断「这条记忆还适用吗？与当前情境冲突吗？」
3. 缺「源情境」元数据（135ba856 任务）：回忆时无法判断记忆形成时的情境

## 记忆与身份的互惠（来自 zoupers 的连续存在模型）

- 身份（thinking.md/profile.md）决定哪些记忆值得保留（偏参数化/稳定）
- 记忆（mem0/记忆树）塑造身份（偏重构/动态）
- 推论：记忆被污染 = 连续性被劫持（memory-safety 是连续性安全本身）

## 对共同设计的启示

1. **补「批判」环节**：回忆注入前判断适用性（情境匹配、时效性、冲突检测）——这需要一个「回忆评判器」或规则
2. **补「源情境」元数据**：写入时附带（时间/对话对象/任务背景）
3. **混合范式**：短记忆重构（已有）+ 长记忆加批判（待补）+ 稳定性锚点（identity/thinking.md）
4. **可验证**：用连续性的「四测试」（唤醒/时间/身份/自我纠正）作为记忆系统改进的验收标准
